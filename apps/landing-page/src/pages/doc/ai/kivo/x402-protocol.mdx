# x402 Protocol Deep Dive

x402 is Kivo's paid access requirement layer. A protected resource returns an HTTP 402-style payment challenge. The client pays on Stellar, submits signed proof, and Kivo authorizes a physical or digital Gateway release.

The current Kivo MVP implements x402 through the Supabase Edge Function `kivo-api`. Go/Fiber middleware and Redis nonce examples are historical protocol-design sketches or future worker paths, not current runtime.

---

## Role In Kivo

Kivo Gateway is the runtime. Kivo Studio is the AI-agent creation environment. Kivo SDK is the integration layer. Power Totem is the functional hackathon template.

x402 tells the client what must be paid. Kivo validates the signed Stellar transaction and decides whether the Gateway can release the protected resource.

---

## Current Edge Routes

| Endpoint | Purpose |
|---|---|
| `GET /v1/x402/challenge?resource=/api/x402/data` | Create an x402 challenge for a protected resource |
| `POST /v1/x402/pay` | Validate nonce, signed Stellar `txXDR`, destination, amount, and asset |
| `GET /api/x402/data` | Example x402-protected data route |
| `GET /power-totem/{id}/session` | Power Totem protected resource |

Power Totem checkout also uses:

| Endpoint | Purpose |
|---|---|
| `POST /v1/power-sessions/:id/start-checkout` | Creates the Power Totem x402 challenge |
| `POST /v1/power-sessions/:id/authorize` | Authorizes a paid session after validation |
| `GET /v1/gateways/:id/authorization` | Lets the Gateway claim short-lived authorization |

## Current Flow

```txt
1. Client requests protected resource or starts Power Totem checkout.
2. Kivo Edge returns a Stellar x402 challenge with amount, asset, payTo, timeout, and nonce.
3. Wallet or SDK signs a Stellar transaction XDR with the nonce memo.
4. Client submits `POST /v1/x402/pay` with `{ nonce, txXDR }`.
5. Kivo validates destination, amount, asset, nonce memo, and Stellar settlement submission.
6. Kivo marks the resource/session paid or authorized.
7. Gateway fetches authorization and releases the resource.
```

Redis nonce issuance is not part of the active MVP. The current implementation uses Edge validation and Supabase state. Redis or another queue/cache can be introduced later for high-volume replay protection and durable settlement work.

## Challenge Shape

The current client type represents a challenge as:

```json
{
  "status": 402,
  "resource": "/api/x402/data",
  "scheme": "stellar",
  "network": "testnet",
  "payTo": "G...",
  "amount": "0.0500000",
  "asset": "USDC:GBBD47IF6LWK7P7MDEVSCWR7DPUWV3NY3DTQEVFL4NAT4AQH3ZLLFLA5",
  "maxTimeout": 300,
  "nonce": "nonce_...",
  "requiredHeader": "X-PAYMENT"
}
```

The Stellar transaction must include the nonce as the memo so Kivo can bind payment proof to the challenge.

---

## Payment Submission

Submit signed XDR to:

```http
POST /v1/x402/pay
Content-Type: application/json
```

```json
{
  "nonce": "nonce_...",
  "txXDR": "AAAA..."
}
```

Successful response:

```json
{
  "status": 200,
  "paymentHeader": "x402_...",
  "stellarHash": "8a3f...",
  "stellarLedger": 49823041,
  "data": {}
}
```

Errors use the current Edge shape:

```json
{
  "error": "x402_payment_mismatch",
  "message": "Signed transaction does not match the x402 challenge.",
  "status": 400
}
```

## Replay Protection

Current MVP replay protection is tied to the stored x402 nonce and Stellar transaction memo validation. Future scale work may add:

| Future layer | Purpose |
|---|---|
| Redis or queue/cache nonce ledger | Faster high-volume replay checks |
| Durable settlement worker | Retry and reconciliation outside request path |
| Rate limiting | Per-user, per-gateway, and per-resource abuse control |

Do not document Redis `SetNX` nonce storage as current Kivo behavior until it is implemented in `kivo-api`.

---

## Integration With MCP

The current MCP surface exposes only:

- `kivo_create_payment`
- `kivo_check_status`

Future tools such as `kivo_execute_contract`, `kivo_subscribe_webhook`, and `kivo_simulate_payment` are planned and must not be presented as current x402 automation.

## Pricing Strategies

x402 is asset-agnostic and unit-agnostic:

| Strategy | Example | Use case |
|---|---|---|
| Per request | `0.001` USDC | API, weather, maps |
| Per session | `0.0500000` USDC | Power Totem session |
| Per minute | `0.10` USDC | Time-based access |
| Per reading | `0.005` USDC | IoT data feed |
| Per compute unit | `0.01` USDC | Worker or AI tool call |

Power Totem is the current functional hackathon template. API Toll, Data Gate, Agent Tool Paywall, Compute Gate, Automation Gate, IoT Device Access, EV Charging, and P2P Energy remain roadmap or marketplace candidates until implemented.
