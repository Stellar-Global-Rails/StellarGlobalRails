# Auth & Security

Kivo's current MVP runtime is the Supabase Edge Function `kivo-api`. Dashboard, Studio, and SDK calls use Supabase Auth JWTs. Gateway runtime calls use a paired gateway token in `x-gateway-token`. x402-protected resources use payment proof in `X-PAYMENT`. Etherfuse webhooks use signed webhook verification.

Go/Fiber middleware, Redis nonce/rate limiting, Fly.io TLS, and Go worker goroutines were part of an older implementation plan. They are not the current MVP runtime.

---

## Current Auth Realms

| Realm | Current mechanism | Used by |
|---|---|---|
| Dashboard and Studio | `Authorization: Bearer <supabase_jwt>` | Dashboard, Studio routes, SDK client calls, MCP routes |
| Gateway runtime | `x-gateway-token` | Gateway heartbeat, authorization polling, gateway events |
| x402 resource unlock | `X-PAYMENT` | x402 resource access after payment proof |
| Etherfuse webhook | `X-Signature` | Etherfuse signed webhook delivery |

The Edge function verifies Supabase users by calling Supabase Auth with the bearer token. It does not currently rely on Go/Fiber JWT middleware.

---

## Supabase JWT

Dashboard and Studio calls require a Supabase Auth session token:

```txt
Authorization: Bearer <supabase_jwt>
```

Current protected surfaces include:

- `GET /v1/dashboard`
- Device, payment, webhook, API key, MCP, and workflow routes
- Studio routes such as `POST /v1/studio/intents` and `POST /v1/studio/flows`
- Power Totem and Power Session management routes
- Etherfuse proxy routes that are dashboard-facing

Supabase Row Level Security remains part of the database security posture for dashboard-facing tables. The Edge function can use `SUPABASE_SERVICE_ROLE_KEY` server-side, but that key must never reach the browser.

---

## Gateway Tokens

Power Totem pairing creates a gateway token that is shown once. Gateways authenticate runtime calls with:

```txt
x-gateway-token: kgw_...
```

Current gateway routes:

| Endpoint | Purpose |
|---|---|
| `POST /v1/gateways/:id/heartbeat` | Marks a gateway online |
| `GET /v1/gateways/:id/authorization` | Lets the gateway fetch a short-lived authorization |
| `POST /v1/gateways/:id/events` | Records gateway release/completion/failure events |

The gateway token is scoped to its paired gateway. A token cannot operate another gateway route.

---

## x402 Verification

The current Edge x402 path issues and validates payment requirements through:

| Endpoint | Purpose |
|---|---|
| `GET /v1/x402/challenge?resource=/api/x402/data` | Creates a payment challenge |
| `POST /v1/x402/pay` | Validates nonce memo, destination, amount, asset, and signed Stellar `txXDR` |
| `GET /api/x402/data` | Example x402-protected data route |
| `GET /power-totem/{id}/session` | Power Totem protected resource |

The current implementation uses Supabase persistence and Edge validation. Redis nonce/rate limiting is a future scaling option, not the current MVP implementation.

---

## Etherfuse Webhooks

Etherfuse webhook delivery is authenticated with `X-Signature`. Kivo stores Etherfuse credentials only as server-side Edge Function secrets:

```txt
ETHERFUSE_API_KEY
ETHERFUSE_WEBHOOK_SECRET
ETHERFUSE_WEBHOOK_VERIFY
```

Rules:

- Never expose `ETHERFUSE_API_KEY` to the browser.
- Never log raw provider secrets.
- Verify `X-Signature` outside local/sandbox exceptions.
- Store provider events for audit and reconciliation.
- Keep Etherfuse as an anchor/funding rail; it does not unlock Gateway resources by itself.

---

## Error Shape

Current Edge errors use:

```json
{
  "error": "machine_readable_code",
  "message": "Human-readable message.",
  "status": 400
}
```

Older `{ "error": "...", "code": "..." }` examples belong to retired Go/Fiber planning docs and should not be treated as current.

## Security Checklist

| Control | Current status |
|---|---|
| Dashboard auth | Supabase JWT |
| Gateway auth | Hashed/paired gateway token via `x-gateway-token` |
| x402 validation | Edge validation of nonce memo, destination, amount, asset, and signed XDR |
| Webhook integrity | Etherfuse `X-Signature` |
| Server-side secrets | Supabase Edge Function secrets |
| Browser secret exposure | Forbidden |
| RLS | Required for dashboard-facing Supabase tables |
| Rate limiting | Future hardening item |
| Redis nonce cache | Future scaling option, not current MVP |
| Fly.io TLS | Retired runtime path; current frontend/API path uses Vercel/Supabase TLS |

Power Totem demos must use safe low-voltage hardware only. Kivo Gateway authorizes resource release; it does not directly switch unsafe mains power.
