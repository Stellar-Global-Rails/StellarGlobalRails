# Deployment

Kivo's MVP deployment path is Vercel + Supabase. Fly.io and the old Go backend are retired from the MVP path.

| Layer | Provider | Path |
|---|---|---|
| Frontend | Vercel | `apps/kivo/web` |
| API runtime | Supabase Edge Functions | `supabase/functions/kivo-api` |
| Auth | Supabase Auth | Same Supabase project |
| Data | Supabase Postgres | `public.kivo_*` tables |
| Storage | Supabase Storage | Proofs and device assets when needed |
| Secrets | Supabase Edge Function secrets | Server-only API keys and provider credentials |
| Settlement | Stellar testnet | Horizon |
| Anchor/ramp | Etherfuse Devnet/Sandbox | Server-side proxy |

Any remaining Go/Fly references are historical or future-worker context, not active deployment guidance.

---

## Frontend

Set these on Vercel:

```txt
VITE_SUPABASE_URL=https://<project-ref>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=...
VITE_KIVO_API_URL=https://<project-ref>.supabase.co/functions/v1/kivo-api
```

Build command:

```bash
cd apps/kivo/web
npm install
npm run build
```

Never expose service-role, Etherfuse, webhook, or Stellar secret material through Vercel environment variables.

## Supabase Edge Function

Deploy:

```bash
supabase functions deploy kivo-api --project-ref <project-ref> --use-api --no-verify-jwt
```

API base URL:

```txt
https://<project-ref>.supabase.co/functions/v1/kivo-api
```

Etherfuse webhook URL:

```txt
https://<project-ref>.supabase.co/functions/v1/kivo-api/v1/etherfuse/webhook
```

`verify_jwt` is disabled at the function gateway because the same Edge runtime handles public health checks, x402 challenges, and third-party webhooks. The function enforces auth route-by-route.

## Preflight

```powershell
powershell -ExecutionPolicy Bypass -File apps/kivo/scripts/preflight.ps1 -ApiUrl https://<project-ref>.supabase.co/functions/v1/kivo-api
```

Go/no-go:

- `GET /v1/health` returns `200`.
- `GET /v1/deploy/checks` reports no blocked production-critical checks.
- `GET /v1/etherfuse/status` returns expected mode/configuration.
- `POST /v1/studio/intents` and `POST /v1/studio/flows` work for an authenticated user.
- Power Totem can be created and paired.
- Gateway heartbeat marks the gateway online.
- `POST /v1/power-sessions/:id/start-checkout` creates an x402 challenge.
- `POST /v1/x402/pay` validates signed Stellar XDR.
- Gateway authorization and events complete the demo loop.
- Vercel frontend points to the Supabase Edge Function.
- Supabase Auth login works in production.

## Retired Runtime

The old Go backend and Fly.io deployment are not a temporary fallback for the MVP. They may remain in repository history or future architecture notes, but current deployment work should target:

```txt
Vercel frontend -> Supabase Edge Function kivo-api -> Supabase Postgres/Auth/Secrets -> Stellar/Etherfuse
```
